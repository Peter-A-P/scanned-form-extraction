# Gemma 4 E4B fine-tuned to read NIST tax forms

A QLoRA adapter on `google/gemma-4-E4B` that reads the page images of one page and writes its fields as JSON. Trained and measured in Forms That Read Themselves (package `legible`), which compares frontier vision models, fine-tuned small vision models and OCR pipelines on scanned forms with known answers. Run `4b-nist-v1120-s0-819cff2552`. This card is written by `legible cards` from the run's records and graded reads; no number in it is typed by hand.

## What it reads and what it writes

Input: the document's pages as images, in page order, then the instruction every reader in the project is sent (`legible.prompt`, version 1), which describes each field and gives the JSON Schema. The adapter was trained on that instruction and nothing else.

One JSON object a page, for whichever of the twenty 1988 form faces it is: 20 schemas, 1,113 text fields in all, every value a string or null. The face's own prompt names it and lists its fields; the fields are the NIST tables' (`legible/schema/nist_fields.json`), check marks and signatures left out.

## How it was trained

Project 06's QLoRA recipe with a vision encoder (`legible/train/vision.py`): one user turn of page images then the instruction, one assistant turn of the truth's JSON, the loss on the answer's tokens only. Every training document is from the split's train part; a held-out document refuses the set (`legible/train/dataset.py`).

## Failure modes

- **A form design it has not seen.** Not measured on this corpus: NIST's twenty faces are fixed, and every face it reads it saw in training. On FARA and DeepForm, where it was measured, the fine-tunes read worse on templates they did not see and the frontier models do not (the README's template gap tables); expect worse on a form unlike its training set.
- **A bad scan.** On NIST's 300 curve pages, degraded in the project's five reproducible steps (docs/degradation.md): level 0 74.9% (70.9 to 78.6), level 1 75.6% (72.1 to 78.8), level 2 77.5% (74.5 to 80.3), level 3 75.1% (71.5 to 78.5), level 4 72.6% (69.4 to 75.7). Beside it: GPT-6.1 Sol level 0 94.9% (93.8 to 95.8), level 1 95.1% (93.7 to 96.2), level 2 94.7% (93.3 to 95.7), level 3 74.6% (68.3 to 80.7), 239 of 300 read so far.
- **Confidently wrong.** Its own token probability is not a reason to skip review. Of its dev fields written at a token probability of 0.999 or more (3,317), 81.4% (77.7 to 85.0) are right; the commonest error there is a null where the form carries a value (365). At 99% accuracy it sends 100.0% (100.0 to 100.0) of its test fields to a person, since no threshold reached 99% on dev. The probability measures how sure the model is of its habit, not whether the page agrees (docs/review.md).
- **Not non-inferior to the frontier.** Project 03's gate cannot decide on this corpus at a 3-point margin per field (above). Do not take it as a drop-in for a frontier model's read.
- **Malformed answers.** 7.0% (4.8 to 9.4) of its test answers did not parse as JSON. It is read freely: holding the fine-tunes to the schema's grammar was tried on dev and rejected, because it pushed them off their trained spacing and the DeepForm E2B then answered null for every field (docs/rejected.md). A caller must count a parse failure as a document to type by hand.
- **Invented fields.** 3.3% (2.7 to 4.0) of scored fields carry a value where the form's box is blank.
- **One instruction.** Trained on one prompt and one schema; another wording, another field list or another language is untested.

## Intended use

Reading NIST tax forms of the kind it was trained on into JSON for a person to check, at a fraction of a frontier model's cost per page; and reproducing the measurements in this card. Plan on a person checking every field: no confidence measured in the project separates right fields from wrong ones well enough to skip review at 99% (the README's honest limitation).

## Out of scope

- Any decision about a person made on its output without a person checking it.
- Handwriting, other form families, long multi-page documents, or a form whose type is unknown.
- Unattended use on form designs it was not trained on, where it is worst.
- Pages that are not public: it was measured on public records and datasets only.

## Loading it

```python
from peft import PeftModel
from transformers import AutoModelForImageTextToText, AutoProcessor

base = AutoModelForImageTextToText.from_pretrained("google/gemma-4-E4B", revision="411aa17b749aa952df1359d2dcea73917a544d9a")
model = PeftModel.from_pretrained(base, "<this repository>")
processor = AutoProcessor.from_pretrained("<this repository>")
processor.image_processor.max_soft_tokens = 1120
```

Read it at temperature 0, with the prompt `legible.prompt.build_prompt` writes for its schema; the project served it merged into the bf16 base under vLLM (`legible serve merge`).
